# AI development workflow comparison

Reviewed 2026-10-08. First English group reviewed before Korean/Japanese
translation. Published originals and supplements use revision/sourceRevision 1.

| Stable ID         | Situation                                               | Selection priority                                             | Priority favoring a peer                                      |
| ----------------- | ------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------- |
| `no-extra-skills` | Correct a school club venue label                       | Existing instructions and checks already cover a clear task    | Shared, dependent requirements need durable agreement         |
| `spec-kit`        | Coordinate concert booking and waitlist notification    | Trace one rule through specification, plan, tasks, and code    | A bounded correction needs less setup                         |
| `superpowers`     | Repair a recipe scaling regression                      | Repeatable test-first work and review                          | Durable requirements and change tracking are the primary need |
| `openspec`        | Add workshop rescheduling while preserving confirmation | Review current behavior against a proposed specification delta | An isolated label correction needs less documentation         |

This is a comparison of approaches and tool packages, not a claim that every
entry is a single `SKILL.md`, an exclusive choice, or a scale tier. Spec Kit and
OpenSpec both support existing and new projects. Superpowers includes planning
as well as execution skills. No additional skills still means planning,
existing instructions, acceptance criteria, and verification. Existing useful
skills are preserved. Select by uncertainty, dependencies, risk, collaboration,
handoff, existing practices, runtime support, and setup/maintenance cost.

Do not turn vendor comparisons, stars, or procedural claims into measured
quality rankings. Installation, activation, and invocation are separate states;
record current official sources and actual external-agent evidence. Tools are
examples, not an exhaustive or mandatory catalog. Scoped complementary skills
can coexist after plan/task/specification ownership is clear.

Source ledgers live in each article's EN/KO/JA supplement and diagram brief.
Official sources reviewed: OpenAI project-instruction documentation, Agent
Skills overview, Spec Kit installation/integrations/SDD/existing-project docs,
Superpowers README and brainstorming/TDD skills, OpenSpec README/workflows and
supported-tool docs. Product-specific claims are labeled as such. Setup details
must be refreshed before the external agent installs or invokes anything.

All four article bodies introduce service, users, ordinary actions, problem,
solution, result, then concept/limits. Main reading estimates are below 60
seconds in every language. Supplements carry detailed selection, setup,
failure/unsupported-environment handling, and source claims. Independent static
diagrams show each mechanism without pretending to execute an agent or test.
