## Selection & comparison

This example prioritizes the difference between current behavior and a proposed change. OpenSpec keeps specifications and change artifacts that can evolve together. Spec Kit may fit a team prioritizing its specification-to-implementation process; Superpowers emphasizes repeatable execution skills. Existing instructions may suffice for a bounded correction. OpenSpec also supports new projects; “existing project” is an example, not a hard eligibility rule. Compare compatibility and maintenance cost rather than vendor claims about competing tools.

## Applications

The workshop already confirms each booking. The proposed rule allows a member to move a booking at least 24 hours before the session; this threshold is a fictional accepted product choice. Record the added rescheduling scenario while preserving confirmation behavior. The change contains a proposal, specification delta, design, and tasks. Check the accepted time boundary and unchanged confirmation behavior. Review synchronization of the delta into current specifications and keep the archived rationale.

## Implementation & cautions

In the external agent, inspect the current official installation and supported-tool documentation, runtime, project, and existing setup. Install only the selected scope under existing authority, initialize the appropriate integration, and review generated files. The CLI performs setup and artifact operations; the agent writes and applies the change through its installed workflow. Invocation spelling depends on the tool; use the form printed for the selected integration. Confirm an actual planning artifact was produced. Verification commands depend on the installed profile, so do not assume every optional command exists. Archiving or checked task boxes do not prove working behavior: run the project’s relevant checks and report gaps. Reuse these artifacts for kickoff’s planning and work records.
