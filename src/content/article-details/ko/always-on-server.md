## 선택·비교

실행 환경 직접 제어, 지속 연결, 프로세스 단위 작업이 중요할 때 대기 프로세스를 검토합니다. 정적 호스팅은 미리 만든 파일을 제공하고 쓰기에는 다른 서비스가 필요합니다. 관리형 함수는 호출 배정을 제공자에게 맡기며 수명 제약도 다를 수 있습니다. 여러 호스팅 방식이 DB를 사용하므로 영속 저장만으로 상시 프로세스를 택하지는 않습니다.

## 응용 사례

도서관 예제는 대기 프로세스와 외부 기록 저장소를 나눕니다. 읽기와 저장이 프로세스를 통과합니다. 재시작하면 실행 세대와 호출 수는 바뀌지만 기록은 남습니다. 초기화는 모형 전체를 지웁니다. 실제 운영에는 상태 확인·영속 저장·백업·복구 연습도 필요합니다. 프로세스 재시작 성공은 데이터 복원 가능성의 증거가 아닙니다.

## 구현 참고·주의점

패치·감시·용량·복구 담당자를 정합니다. 확보한 용량은 유휴 시간에도 비용을 만들 수 있으므로 작업량과 제공자의 현재 조건을 비교한 뒤 견적을 냅니다. 응답이 유실되면 같은 요청이 재전송될 수 있으므로 중복 처리는 앱 규칙으로 정합니다. 관리형 플랫폼이 서버 업무 일부를 맡아도 앱 동작과 데이터 책임이 없어지지는 않습니다. 예제는 실제 서버나 저장소에 연결되지 않습니다.
