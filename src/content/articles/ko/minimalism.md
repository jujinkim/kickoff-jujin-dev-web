## 정의

인터페이스의 미니멀리즘은 작업을 뒷받침하지 않는 것을 제거하는 전략입니다. NN/g는 요소와 콘텐츠 모두를 대상으로 이 축소를 설명합니다. 여기서 작업은 짧은 글을 평가하고 나중을 위해 저장하는 것입니다. 제목·요약·읽기 시간·저장에는 각각 정해진 역할이 있습니다. [NN/g: Characteristics of Minimalism](https://www.nngroup.com/articles/characteristics-minimalism/)

이는 표면 외형을 다루는 플랫 디자인과 다릅니다. 평면 인터페이스는 정보가 가득할 수 있고 미니멀한 인터페이스는 유용한 그림자를 남길 수 있습니다. 흰 배경, 단색 색상표, 매우 넓은 빈 여백은 이 예제의 합격 기준이 아닙니다. 제거 후에도 읽기 작업이 보존되는지가 질문입니다.

미적 축소가 기능 삭제가 되어서는 안 됩니다. NN/g의 미적·미니멀한 디자인 휴리스틱 설명은 작업에 필요한 모든 요소의 보존을 강조합니다. 저장 행동이 없는 아름다운 빈 카드는 이 예제에서 실패입니다. [NN/g: Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)

## 특징과 예시

**설명용 예제 — 중복을 줄이고 작업을 보존합니다.** 중립 카드는 일곱 예제의 공통 콘텐츠를 정합니다. 확장된 시작 사례에는 각 제거를 명시하기 위해서만 장식 배지와 중복 행동을 추가합니다.

1. **입력:** 현장 노트, 글을 저장하는 세 가지 방법, 5분, 원래 저장 버튼, 저장됨 상태입니다. 장식 배지 두 개와 중복 저장을 추가합니다. 배지는 고유 정보를 전달하지 않고 두 버튼은 같은 행동을 합니다.
2. **초기 상태:** 확장된 예제에서 추가 요소가 모두 보입니다. 제목은 글을 식별하고, 요약은 범위를 설명하고, 시간은 읽을지 판단하도록 돕고, 저장은 글을 보관하게 합니다. 여기서 배지와 중복 버튼은 기능이나 사실을 추가하지 않습니다.
3. **동작:** 배지 두 개와 중복 저장을 제거합니다. 원래 버튼과 모든 고유 정보는 유지합니다. 저장에 포커스를 둔 뒤 키보드나 포인터로 실행합니다.
4. **결과:** 줄인 카드에도 제목·요약·시간·원래 행동이 있으며 저장됨이 실행을 확인합니다. 포커스는 컨트롤에 남고 결과가 알림으로 전달됩니다. 초기화·새로고침은 예제 내부 상태를 지웁니다. 계정에는 저장하지 않습니다.

```text
유지 1: 현장 노트 — 식별
유지 2: 글을 저장하는 세 가지 방법 — 범위
유지 3: 5분 — 읽기 시간 정보
유지 4: 저장 / 저장됨 — 행동과 결과
제거 5–6: 장식 배지 — 고유 정보 없음
제거 7: 중복 저장 — 같은 국소 맥락에서 같은 행동
반례: 원래 저장 제거 — 더는 작업할 수 없음
```

개수는 이 가상 사례를 설명하며 인터페이스 요소 수의 권장 상한이 아닙니다. 실제 긴 페이지라면 버튼 두 개가 타당할 수 있습니다. 중복이 불필요하다는 판단은 명시한 국소 조건에만 해당합니다. 접근 제한을 알리는 배지도 장식이 아닌 정보입니다.

반례는 남은 저장까지 제거합니다. 정렬이 차분해 보여도 빈 공간은 요구사항의 실패를 드러냅니다. 좁은 화면에서는 패널을 순서대로 쌓습니다. JavaScript 없이도 정적 예시와 번호 순서를 읽을 수 있습니다. 색과 그림자가 없어도 문구가 의미를 보존합니다.

## 장점과 제약

명시한 추가 요소를 제거하면 제목과 원래 저장 주변의 경쟁 요소가 줄어듭니다. 이는 제작한 예제의 관찰이며 주의력이나 완료 시간의 개선을 측정한 결과가 아닙니다. 실제 제품에서는 설명 없이 독자가 글을 식별하고 관련성을 판단하고 행동을 찾는지 확인하세요.

어려운 부분은 무엇이 불필요한지 정하는 일입니다. 전문가에게 익숙한 안내가 초보자에게는 필수일 수 있습니다. 보조 상태는 오류가 난 뒤에만 중요할 수도 있습니다. 선호하는 화면 사진 대신 작업 목록을 기준으로 줄이세요. 식별·맥락·가능한 행동·현재 상태·복구를 모두 검토해야 합니다.

여백은 이 역할들을 구분할 수 있지만 요약과 저장 사이를 멀리 이동하게 해서는 안 됩니다. 시각적 무게를 줄인다고 글자를 흐리게 해서도 안 됩니다. WCAG의 일반 텍스트 대비 기준은 명시된 예외를 제외하고 보통 4.5:1입니다. 성긴 설계에서도 남은 글은 읽을 수 있어야 합니다. [W3C: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 같은 범주의 비교

같은 카드로 정보 편집과 표면 스타일의 차이를 분명히 합니다. 아래 축은 공통 순서를 따릅니다.

- **표면·깊이:** [브루탈리즘](/ko/catalog/brutalism/)은 가공 적은 구조, [네오브루탈리즘](/ko/catalog/neobrutalism/)은 단단한 깊이, [글래스모피즘](/ko/catalog/glassmorphism/)은 반투명 층, [뉴모피즘](/ko/catalog/neumorphism/)은 부드러운 부조를 보여줍니다. [스큐어모피즘](/ko/catalog/skeuomorphism/)은 물리적 참조를 넣고 [플랫 디자인](/ko/catalog/flat-design/)은 모사한 깊이를 줄입니다. 미니멀리즘 자체는 어느 표면도 규정하지 않습니다.
- **장식:** 가공 적은 제목, 굵은 외곽선, 흐림, 부드러운 하이라이트, 책갈피 모양은 의도한 표현을 돕는다면 남길 수 있습니다. 평면 처리는 깊이 효과를 제거하고, 미니멀리즘은 남긴 장식이 작업과 맥락을 돕는지 묻습니다.
- **보존 정보:** 일곱 예제 모두 제목·요약·시간·저장을 유지합니다. 미니멀리즘 사례는 추가로 중복 배지·행동과 고유 정보를 구분합니다. 고유 안내를 제거하면 비교 조건이 불공정하게 바뀝니다.
- **행동 단서:** 브루탈리즘의 밑줄, 네오브루탈리즘의 테두리, 유리·뉴모픽 프레임의 독립적인 컨트롤, 스큐어모픽 표시, 평면 외곽선 모두 저장을 보완할 수 있습니다. 미니멀리즘은 주변 장식을 없애도 필요한 단서를 유지합니다.
- **배경 의존성:** 미니멀리즘은 불투명도를 결정하지 않습니다. 유리와 조합하면 배경 대비 문제를, 부드러운 부조와 조합하면 색조 문제를 이어받습니다. 가공 적은 표면, 굵은 외곽선, 종이, 평면 변형도 적절한 전경·배경 선택이 필요합니다.
- **상태 가시성:** 요소가 줄어도 상태 설명이 줄어서는 안 됩니다. 저장됨과 보이는 포커스는 모든 변형에 남습니다. 반례는 행동을 통째로 잃습니다. 이는 성공적인 축소의 강화가 아니라 기능 손실입니다.

## 선택·조합 조건

작업이 명확하고 제거 후보가 해당 맥락에서 확실히 중복일 때 사용하세요. 삭제마다 이유를 적으세요. “이 작은 카드에서 다른 버튼이 정확히 같은 행동을 한다”가 “버튼 하나가 더 깔끔하다”보다 강한 근거입니다. 검토에서 예외도 명시하세요.

장식적 깊이를 없애도 컨트롤이 흐려지지 않는다면 평면 표면과 조합하세요. 남은 글에 통제된 읽기 좋은 배경과 불투명 대안이 있을 때만 유리와 조합하세요. 가공 적은 구조가 읽기 순서와 의도한 분위기를 유지한다면 브루탈리즘과 조합하세요. 이는 필수 미관이 아니라 조건입니다.

발행 전에 초기·포커스·저장·복구 상태를 검토하세요. 실행 전에는 충분해 보여도 이후 확인이 누락될 수 있습니다. 각 상태에 같은 작업 목록을 적용하고, 성긴 화면을 만들기 위해 필요한 맥락을 숨기지 않은 채 좁은 레이아웃을 살펴보세요.

## 관련 글과 출처
