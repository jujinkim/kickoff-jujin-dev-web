## 定義

フラットデザインは表面処理に関する考え方です。光沢、隆起、深いくぼみよりも、形を二次元的に見せます。Interaction Design Foundationは単純な二次元要素と説明しています。この記事では明るい配色を指定せず、模倣した奥行きの削減に注目します。平面的なカードでも多くの情報を持てます。[IxDF: Flat Design](https://ixdf.org/literature/topics/flat-design)

ミニマリズムは、作業にどの情報や機能が必要かを問います。フラットデザインは、それらの表面をどう見せるかを問います。グラデーションを除けば、文やボタンを削除せずに後者を変えられます。NN/gも、よく重なるこの二つを明確に区別しています。密な表に平面的なセルを使い、要素の少ないページに隆起したボタンを置くこともできます。[NN/g: Characteristics of Minimalism](https://www.nngroup.com/articles/characteristics-minimalism/)

実用上の問いは、装飾的な奥行きがなくなっても保存を識別できるかです。二次元の表面だからといって、操作対象を普通の本文に似せる必要はありません。

## 特徴と実例

**説明用の例 — 奥行きを除いても操作の手がかりは必要です。** 中立の基準と平面的な変形例は同じ内容です。別の不採用例は、平面化と同時に操作対象の境界を除く問題を示します。

1. **入力:** フィールドノート、記事を保存する3つの方法、5分、保存、保存済みの結果を持つ読書カードです。ここでの光沢は情報ではなく装飾です。
2. **初期状態:** 光沢のある枠と、境界が見える保存ボタンを考えます。基準は読書作業を示します。平面的な変形例は全ての文字を残し、グラデーションと影を除きます。
3. **操作:** グラデーションと影をnoneにし、保存の輪郭とラベルは残します。Tabで保存に移り、フォーカスの輪郭を確認してからEnter、Space、またはクリックで実行します。
4. **結果:** 表面は平面的なままで、結果は保存済みになります。操作前からボタンを識別でき、フォーカスも見えます。リセットや再読み込みで例の初期状態に戻ります。保存はアカウントに永続化されません。

```css
/* 説明用の変更値であり、全てのフラットデザインの仕様ではありません。 */
.flat-card {
  background-image: none;
  box-shadow: none;
}
.flat-card button {
  border: 2px solid currentColor;
}
.flat-card button:focus-visible {
  outline: 3px dashed currentColor;
  outline-offset: 3px;
}
```

2pxの境界線と3pxのフォーカスの輪郭は、この例のための選択です。重要なのは、奥行きを除いても独立した操作の手がかりが残る関係です。不採用例の保存は境界などの区別がなく、周囲の本文に見えます。意図的な反例であり、実行する追加の操作対象ではありません。

320pxでは文字を縮めずにパネルを縦に並べます。JavaScriptがなくても見える説明と静的な状態例を読めます。色や影を除いても、保存済みの文字と操作対象の形は消えません。

## 利点と制約

このカードは少数の単色の塗りと輪郭で表現できます。そのため、例の視覚的な判断を調べやすくなります。これは高速な読み込み、成約率の向上、自動的なアクセシビリティを証明しません。その主張には実際の実装と対象者についての根拠が必要です。

主な危険は、奥行きと操作のシグニファイアを同時に除くことです。NN/gは、区別の弱い操作対象でクリック可能か分からなくなる問題を説明しています。この例の保存ラベル、見える境界、一貫した位置は別々の手がかりです。まだ操作を見つけていない人にとって、ホバー時だけの変化は遅すぎます。[NN/g: Flat Design](https://www.nngroup.com/articles/flat-design/)

この境界線は設計上の選択であり、WCAGが全ボタンに枠を要求するという意味ではありません。W3Cは、操作対象と状態の識別に必要な視覚情報に、規定の例外を除いて隣接色との3:1のコントラストを求めています。文字で十分に識別できる操作対象に囲み枠は必須ではありません。実際の設計が頼る手がかりを検査してください。[W3C: Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 同じ分類の比較

同じ読書作業を六つの軸で順に比較します。スタイル名だけで使いやすさは決まりません。

- **表面・奥行き:** [ブルータリズム](/ja/catalog/brutalism/)は加工の少ない構造、[ネオブルータリズム](/ja/catalog/neobrutalism/)は硬い影、[グラスモーフィズム](/ja/catalog/glassmorphism/)は透明な層、[ニューモーフィズム](/ja/catalog/neumorphism/)は柔らかな浮き彫りを表します。平面処理はこれらの奥行きの手がかりを減らします。[スキューモーフィズム](/ja/catalog/skeuomorphism/)は物の参照、[ミニマリズム](/ja/catalog/minimalism/)は選択に関わります。
- **装飾:** 光沢の除去は、加工の少ない文字、グラフィックの強調、ぼかし、柔らかな影、しおりの参照とは異なります。ミニマリズムは残す表面に関係なく不要な装飾を除けます。平面的なしおりも物の類推を保てます。
- **保持する情報:** 他の例と同様に、平面的な変形例はタイトル、要約、時間、保存をそのまま残します。ミニマリズムの例だけは削除を示すために重複要素を追加します。
- **操作のシグニファイア:** 加工の少ない下線や太い輪郭も平面的にできます。ガラスや柔らかな枠には独立した操作対象が必要です。物のマークはラベルを補い、ミニマリズムは必要な操作を残します。平面的な保存には明示的な境界が残ります。
- **背景への依存:** 不透明な平面の塗りは局所的な背景を制御します。ガラスは背景の変化を見せ、柔らかな浮き彫りには周囲の色調が合う必要があります。ブルータリズム、ネオブルータリズム、スキューモーフィズム、ミニマリズムにもコントラストの選択が必要で、スタイルによる免除はありません。
- **状態の見えやすさ:** 奥行きがなくても保存済みとフォーカスの輪郭は残ります。他の例にも同じ条件が適用されます。硬い影、ぼかし、柔らかなへこみ、しおり、疎な配置だけでは明確な状態の代わりになりません。

## 選択・組み合わせ条件

ラベル、形、位置、一貫した操作で必要な行動を認識できるときに平面処理を選びます。まず初期状態を確認してください。フォーカスやホバーの効果を得る前に、読者は保存を見つける必要があります。何も実行せずに採用例と不採用例を比べます。

内容の構造を理解できれば、平面の表面は密な一覧にもミニマルなページにも使えます。平面的なしおりアイコンは写実的な質感なしに紙のメタファーを保てます。ガラスやニューモーフィックな枠の中の平面的なボタンは、操作対象の認識を装飾的な奥行きから切り離します。

大部分が平面的な画面でも、限定した奥行きで特定の層を説明できます。純粋さを守るより、その例外が何を伝えるかを判断します。逆に、平面的な操作対象が見慣れないだけで影を足さないでください。まずラベル、境界、位置を調べます。これらはこの例に対する筆者の選択条件であり、普遍的な順位ではありません。
