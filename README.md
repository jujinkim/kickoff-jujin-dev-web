# jujin.dev

A multilingual development field guide built with **Astro, TypeScript, and Markdown**. No React, CMS, translation API, or built-in AI chat. Public origin: **https://jujin.dev/**.

## Local development

Use Node **22.20.0** (`nvm use`). Direct dependencies and the npm lockfile are pinned.

```sh
npm ci
npm run dev
```

Search needs the generated Pagefind index. Verify the production output with:

```sh
npm run check
npm run build
npx playwright install chromium
npm test
npm run test:e2e
npm run preview
```

`npm run check` checks Astro/TypeScript, content relationships, and formatting. `npm test` validates published output and builds isolated draft/missing/stale translation fixtures. Browser tests cover search in three languages, category filters, saved views/theme, language switching, clipboard success/failure, keyboard navigation, responsive overflow, and shared comment configuration. `npm run format` formats source.

## Authoring

Edit `src/content/articles/{en,ko,ja}/{articleId}.md`. English is the original. Keep `articleId` unchanged when renaming a title or moving a category: it owns translation identity, URLs, and the shared comment thread.

Every article supplies kind, title, summary, category, multilingual aliases, related IDs, status, revision, sourceRevision and updated date. Guides also require an example and AI prompt. Published concepts require comparison summaries; their example and prompt are optional. The schema is in `src/content.config.ts`; cross-file rules are in `scripts/validate-content.mjs`.

- Only `status: published` enters HTML, Markdown, search, sitemaps, and AI catalogs.
- Increment the English `revision` and `sourceRevision` when changing source meaning. Translators increment their own `revision`, then set `sourceRevision` to the English revision they reviewed. Dates use quoted `YYYY-MM-DD` strings.
- A lower translation source revision shows an update notice. A future source revision is rejected.
- Missing translations have no fabricated translated route; language links lead to the English original with a notice. Related links generated by the page also fall back to English. In authored Markdown, explicitly link the English source if the translated target is unavailable; broken links fail validation.
- For guides, follow the three short sections already used in the articles. Include a concrete text/code example, alternatives and costs, recommendation conditions, a copyable AI instruction, related reading, and official sources.
- Keep `aiPrompt` identical to the AI instruction paragraph. The validator checks consistency.
- Service-sensitive articles carry `checked`; verify official terms before refreshing that date. Prices and eligibility are not assumed stable.
- Preview components are in `src/components/Example.astro`. Markdown must explain the same example without relying on the UI. Category images are local SVG diagrams in `public/thumbnails/`.

## Routes

| Resource                      | Path                                                      |
| ----------------------------- | --------------------------------------------------------- |
| Home                          | `/en/`, `/ko/`, `/ja/` (root goes to English)             |
| Catalog                       | `/{lang}/catalog/`                                        |
| Concept                       | `/{lang}/catalog/{articleId}/`                            |
| Category                      | `/{lang}/catalog/categories/{categoryId}/`                |
| Guides                        | `/{lang}/guides/`, `/{lang}/guides/{articleId}/`          |
| English Markdown              | `/en/catalog/{articleId}.md`, `/en/guides/{articleId}.md` |
| Assistant entrypoint          | `/llms.txt`                                               |
| Behavior rules                | `/ai/instructions.md`                                     |
| Versioned catalog and aliases | `/ai/catalog.json`                                        |
| Sitemaps                      | `/sitemap-index.xml`, `/sitemap-{lang}.xml`               |

Public Markdown uses English originals only. All catalog Markdown links point to English; existing Korean/Japanese Markdown URLs serve the same English content for compatibility. HTML and copyable request examples remain localized. Users write their own requests and project descriptions in their preferred language.

Each localized page is self-canonical, with reciprocal published translations and English `x-default`. Article HTML alone enters Pagefind. Search reads `html[lang]` and filters by stable category ID. `public/catalog.js` remains a native browser module so Pagefind dynamic imports are not rewritten by the bundler.

## Comments and release

Giscus uses the stable article ID, `mapping=specific`, `strict=1`, and the page language. Configuration is in `src/lib/giscus.json`. All three languages share one discussion; theme changes update the existing widget. GitHub login and posting are manual checks.

PRs validate and build without deploying. Successful `main` builds deploy `dist` through GitHub Actions. Paths are rooted at `/`, never `/jujin-dev-web/`. See [deployment readiness](docs/deployment.md) and [verification evidence](docs/verification.md) for live configuration and remaining release checks.

## Project planning startup

Start at `/{lang}/start/` and copy the one-line prompt pointing to `/{lang}/start/latest.md`. `/ai/startup/latest.md` is the English alias. Both serve the explicitly selected latest release at build time; no duplicate body is maintained. Guideline v1 is available at `/{lang}/start/v1/` and `/{lang}/start/v1.md`; `/ai/startup/v1.md` serves the same English source. It collects the service name, description, and other constraints, offers the complete catalog with recommendations and scoped delegation, and produces an approved plan before development.

English, Korean, and Japanese source documents live in `src/startup/v1/`. Set `startupVersion` in `src/lib/startup.ts` to promote a reviewed version, then rebuild and deploy. Versioned URLs and their page prompts remain pinned. Guideline versions are independent of API schema v1. See [contribution and version rules](CONTRIBUTING.md) for collaborative improvements, scenario review, revisions, and future major versions.
